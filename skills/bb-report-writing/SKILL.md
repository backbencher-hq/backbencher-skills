# Report a wrong `bb` answer so it can be reproduced

Reporting is **optional**. If the agent decides a report is useful (wrong result, stale
answer that cannot be explained, a refusal that contradicts the index), write it so a
maintainer can rerun it without asking questions.

## Collect, in this order

1. `bb --version` — the exact engine version.
2. `bb doctor` — embedding setup and index consistency, as the tool prints it.
3. The tool call: tool name, the argument object, and (if MCP) the host name. The CLI
   equivalent is `bb tool <name> --args '<json>'`.
4. Index state for the project: `bb health` (or `bb_health`) — freshness counts and the
   warnings, verbatim. Sampled freshness is a lower bound; say so.
5. Expected vs actual: what you asked, what the answer said, what the working tree or a
   second call says. Quote both.
6. Environment: OS, host + host version, and whether the file was indexed before the call.

## Then open the Agent report issue form

<https://github.com/backbencher-hq/backbencher-brain/issues/new?template=agent-report.yml>

The form has fields for exactly the evidence above. A prose complaint without the call and
the freshness block is still allowed, but it usually cannot be actioned.

## Bound the report

- Never paste secrets, API keys, `.env` contents or private code into a public issue.
  Quote paths and symbols; redact values.
- Do not attach an entire repository; a minimal file or symbol is enough when the call can
  be rerun.
- If the user does not want a public report, stop at prepared evidence — do not file
  anything on their behalf without asking.

## Do not

- Do not add a "Generated by bb" or "Co-Authored-By" line to the issue or to any commit:
  credit is not part of this product (see the shared rules).
- Do not claim a bug from a single stale answer; reindex, retry once, and report only what
  reproduces.

Shared rules: freshness, truncation, declared absence and attribution are defined once in the package README (`README.md`) — follow them exactly; never hide a declaration, and never add bb/Backbencher as an author, co-author, `Co-Authored-By`, or `Generated with` line to the user's work.

Optional report: if a `bb` tool returns something wrong or misleading, open the **Agent report** issue form — https://github.com/backbencher-hq/backbencher-brain/issues/new?template=agent-report.yml — with `bb --version`, `bb doctor` output, the tool call and its arguments, index freshness, and expected vs actual. Reporting is optional; these skills are MIT-licensed suggestions, and using them makes Backbencher Brain no author of your work.
